# 数据字段字典

研究区间：UTC 2023-11-16 00:00:00（含）至 2026-11-16 00:00:00（不含），共 1,096 天。  
每天仅保留 UTC 12:00:00（含）至 13:00:00（不含）内产生的全部区块。  
三条链使用同一套字段、同一套缺失值规则和同一套统计口径。

数据源：SQD Portal `https://portal.sqd.dev/datasets/{dataset}/finalized-stream`，并使用 `GET /timestamps/{unix}/block` 将时间戳解析为“第一个时间戳 ≥ 目标时刻的区块号”。解析后再按区块时间戳严格过滤。`data_source` 记为 `sqd-portal:<dataset>`。

缺失值规则：接口未返回或无法解析的字段在 CSV 中留空，不以 0 填充，不伪造。分叉前不存在的字段（例如 Cancun 之前的 blob 字段）同样留空。

## 基础字段（29 个）

| 字段 | 含义 | 口径 |
| --- | --- | --- |
| chain | 链名 | `Ethereum_Mainnet` / `Polygon_PoS` / `Base` |
| dataset | SQD 数据集名 | `ethereum-mainnet` / `polygon-mainnet` / `base-mainnet` |
| block_number | 区块高度 | 整数 |
| timestamp_utc | 区块时间（UTC） | ISO 8601，例如 `2023-11-16T12:00:11Z` |
| timestamp_unix | 区块时间（Unix 秒） | 整数；筛选条件为 `12:00:00 <= ts < 13:00:00` |
| block_hash | 区块哈希 | 0x 前缀十六进制 |
| parent_hash | 父区块哈希 | 用于链式完整性校验 |
| state_root | 状态根 | `stateRoot` |
| transactions_root | 交易根 | `transactionsRoot` |
| receipts_root | 收据根 | `receiptsRoot` |
| gas_used | 区块 GasUsed | 由十六进制或十进制解析为十进制整数；三链同一字段 |
| gas_limit | 区块 GasLimit | 同上 |
| gas_utilization | Gas 利用率 | `gas_used / gas_limit`；任一侧缺失或 limit=0 则留空 |
| base_fee_per_gas | 基础费用 | 单位 wei；缺失则留空 |
| block_size_bytes | 区块体积 | 字节 |
| blob_gas_used | Blob Gas 用量 | 分叉前或不支持则留空，不填 0 |
| excess_blob_gas | 超额 Blob Gas | 同上 |
| tx_count | 交易笔数 | 该区块交易数组长度 |
| tx_gas_used_sum | 交易 GasUsed 之和 | 仅当全部交易都有 `gasUsed` 时填写，否则留空 |
| failed_tx_count | 失败交易数 | `status==0` 的笔数；若有交易缺 status 则整项留空 |
| contract_creation_tx_count | 合约创建交易数 | `to` 为空的交易 |
| tx_with_to_count | 含收款地址的交易数 | `to` 非空的交易 |
| tx_type_0_count | type 0（legacy）交易数 | |
| tx_type_1_count | type 1（EIP-2930）交易数 | |
| tx_type_2_count | type 2（EIP-1559）交易数 | |
| tx_type_3_count | type 3（blob）交易数 | |
| tx_type_other_count | 其他或未知 type | 无法解析 type 的交易也计入此项，并在完整性字段注明 |
| data_source | 数据来源 | `sqd-portal:<dataset>` |
| tx_data_completeness | 交易字段完整性 | `complete`，或 `partial:missing_gasUsed=N,...` |

## 预留字段（8 个，默认全部留空）

`sload_count`, `sstore_count`, `committed_storage_changes`, `trie_node_reads`, `trie_node_writes`, `keccak_count`, `trie_dependency_depth`, `rtl_comm_bytes`

这八个字段只在取得真实执行追踪或硬件仿真测量结果后才能填写。本次区块头 + 交易回执采集不会填写它们。

## 汇总与审计文件

- `daily_summary.csv`：每天（即每个采样小时）的区块数、交易总量、GasUsed 总量、文件体积、SHA256、字段平均非空率、完成状态。
- `hourly_activity.csv`：同一小时的活动指标（Gas、交易类型分布等）。因每天只采一小时，行数与日汇总一致。
- `data_integrity_audit.csv`：重复区块、时间戳越界、高度连续性、父子哈希、缺失字段备注。
- `collection_progress.csv`：采集进度；`status=complete` 且文件仍存在的日期不会重复下载。
- `failed_tasks.csv`：失败任务及错误信息。
- `sampling_manifest.csv`：固定随机种子下的负载分层抽样结果。
- `gasused_quintiles_by_phase.csv`：各链各阶段 GasUsed 五分位切分点。
- `paper_summary.csv`：供论文使用的抽样完成情况汇总。

## 抽样口径（务必在论文中写明）

1. 将三年区间划分为 12 个连续的三个月阶段，每段从当月 16 日 00:00 UTC 起，至三个月后的 16 日 00:00 UTC 止（不含）。
2. 在**每条链、每个阶段内部**独立计算该阶段所有已采集小时的 GasUsed 总量五分位数。
3. Level 1–5 对应 P0–P20、P20–P40、P40–P60、P60–P80、P80–P100。边界采用左闭右开，最后一档右闭。
4. 每个等级目标抽取 4 个代表性小时：按 GasUsed 分成 4 层后，用固定种子 `20231116` 在层内随机抽取。候选不足时如实记录，不强行凑数。
5. 在选中小时内，将 12:00–13:00 划分为 12 个连续 5 分钟窗口，选取 GasUsed 最接近该小时平均值（总量/12）的窗口；并列时取更早的窗口。
6. 五分位等级只代表已采集的 UTC 12:00–13:00 时段，不能解释为全天网络负载。三条链的 Gas 计量与执行机制不同，不得用绝对 GasUsed 做跨链压力比较。
